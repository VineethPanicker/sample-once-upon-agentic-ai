Workshop notes · Strands Agents SDK on Amazon Bedrock

Once Upon Agentic AI, explained in plain words

A reference for everything we built: an AI Game Master for a fantasy role-playing game. It grew from one chatbot into a small team of cooperating agents. Each chapter below says what the idea is, gives an everyday comparison, shows the code, and records what actually happened when we ran it.

Python 3.13.5 strands-agents 1.61.1 strands-harness 0.3.1 model: Amazon Nova 2 Lite region: us-east-1

The big picture

An AI agent is a language model that can do things, not just talk. A plain chatbot only writes text. An agent can also decide to use tools: roll a die, look something up on the web, read a database, or ask another agent for help. Then it uses the results to write its answer.

Every agent runs the same loop, which Strands calls the agent loop:

  1. Read the instructions (the system prompt) and the user's message.
  2. Think: "Can I answer directly, or do I need a tool?"
  3. If it needs a tool, ask for that tool with specific inputs. Strands runs the tool and hands back the result.
  4. Repeat steps 2–3 as often as needed, then write the final answer.
Everyday comparison

The model is a clever new employee who has read a lot but can't leave their desk. The system prompt is their job description. Tools are the phone, calculator and filing cabinet on the desk. Strands is the office manager: it passes messages back and forth, makes the phone calls the employee asks for, and keeps the conversation notes.

CH 1Your first agent

The smallest possible agent is a model plus a system prompt, the standing instructions that set its role and tone. Calling the agent like a function sends a message and returns its reply.

We also switched on debug logging, which prints what Strands is doing behind the scenes: which model it chose, which region, and how many tools it found.

1_strands_basics/simple_agent.py
import logging
from strands import Agent

# Step 1 – show Strands' internal logs
logging.getLogger("strands").setLevel(logging.DEBUG)
logging.basicConfig(format="%(levelname)s | %(name)s | %(message)s",
                    handlers=[logging.StreamHandler()])

# Step 2 – create the agent with a role
agent = Agent(
    model="global.amazon.nova-2-lite-v1:0",
    system_prompt="You are a game master for a fantasy role-playing game",
)

# Step 3 – talk to it
agent("Hi, I am an adventurer ready for adventure!")
What we saw

The Game Master welcomed us into "the Rusty Flagon" tavern and asked for a name, race, class and one defining trait. The logs showed tool_count=<0>, since this agent has no tools yet. With no model= line, Strands picks Claude Sonnet 4.6 on Bedrock and takes the region from your AWS config.

Remember
  • The model is the brain. The system prompt is the job description. The message is the request.
  • Without tools, everything the agent says comes from its training. It can sound confident and still be wrong.

CH 2Ready-made ("vended") tools

A tool is a function the agent can choose to call. Strands ships with ready-made ones, called vended tools, such as http_request (fetch a web page or API), shell (run a terminal command) and file_editor (create and edit files).

We gave the Game Master http_request, and the system prompt told it where spell data lives: the free Open5e API. Asked about Fireball, the agent built the address https://api.open5e.com/v2/spells/srd_fireball/ itself, fetched it, and answered from the real data.

2_vended_tools/agent_with_vended_tools.py
from strands.vended_tools import http_request

agent = Agent(
    model="global.amazon.nova-2-lite-v1:0",
    tools=[http_request],
    system_prompt="""... look it up on the Open5e API ...
    spells: https://api.open5e.com/v2/spells/srd_<key>/""",
)
agent("What does the Fireball spell do, and how much damage does it deal?")
What we saw

The log showed Tool #1: http_request and Tool #2: http_request. The answer matched the official rules: 8d6 fire damage in a 20-foot radius, a Dexterity save halves it, and +1d6 for each spell slot above 3rd.

Bonus quest: tools that need your permission

shell and file_editor are powerful: they can change files and run programs on your computer. So we wrapped the agent in Human-in-the-loop. Before every tool call it stops and asks you in the terminal to approve or reject.

2_vended_tools/bonus_quest.py
from strands.vended_tools import shell, file_editor
from strands.vended_interventions.hitl import HumanInTheLoop

arcane_scribe = Agent(
    tools=[shell, file_editor],
    interventions=[HumanInTheLoop(ask="stdio")],   # ask in the terminal
    ...
)
Everyday comparison

Human-in-the-loop is like giving an intern a company card that texts you before every purchase. They can still get the job done, and nothing happens without your OK.

CH 3Forging your own tool

Any Python function becomes a tool when you put @tool above it. The model never sees your code. It only sees a short description that Strands builds from three things:

  • the function name (roll_dice),
  • the parameters and their types (faces: int = 6),
  • the docstring: its summary line and its Args: section.

That's why a clear docstring matters: it's the instruction manual the model reads to decide when and how to use your tool.

3_custom_tools/agent_with_dice_roll_tool.py
from strands import Agent, tool

@tool
def roll_dice(faces: int = 6) -> int:
    """Roll a single die with the given number of faces.

    Args:
        faces: Number of faces on the die (e.g. 4, 6, 8, 10, 12, 20). Defaults to 6.

    Returns:
        The rolled value, between 1 and faces.
    """
    import random
    return random.randint(1, faces)

dice_master = Agent(
    model="global.amazon.nova-2-lite-v1:0",
    tools=[roll_dice],
    system_prompt="""... roll 4d6, drop the lowest die.
    Every die must come from the roll_dice tool: call it once per die and never invent a result.""",
)
Lesson learned: having a tool doesn't mean the agent uses it

Rolling four ability scores at "4d6 drop lowest" takes 16 dice. At first, Nova called the tool only 4 to 8 times and invented the rest of the dice in its answer. Adding one sentence to the system prompt ("call it once per die and never invent a result") fixed it: 16 real rolls in every test run.

To check, count the Tool #N: roll_dice lines in the output and compare them with the dice in the answer.

Remember

print(roll_dice.tool_spec) shows exactly what the model is told about your tool. Run it when a tool is being ignored or misused.

CH 4MCP: sharing tools between programs

In Chapter 3 the dice roller lived inside the agent's program. MCP (Model Context Protocol) is an open standard for putting tools in a separate program, an MCP server, that any AI app can connect to: a Strands agent, Claude Code, an IDE, or something written in another language.

We moved the dice roller into a small server at http://localhost:8002/mcp. The Game Master connects to it as an MCP client, asks "what tools do you have?", and calls roll_dice over the network.

Everyday comparison

MCP is like USB for AI tools. Before USB, every printer needed its own special cable. Now any device plugs into any computer. An MCP server is the device, and any MCP-aware app can plug into it.

4_mcp_integration/dice_roll_mcp_server.py (the server)
from mcp.server import FastMCP

mcp = FastMCP(port=8002)

@mcp.tool()                       # expose this function over MCP
def roll_dice(faces: int = 6) -> int:
    ...

mcp.run(transport="streamable-http")   # serve it over HTTP
4_mcp_integration/gamemaster_mcp_client.py (the client)
from strands.tools.mcp import MCPClient
from mcp.client.streamable_http import streamablehttp_client

mcp_client = MCPClient(lambda: streamablehttp_client("http://localhost:8002/mcp"))

gamemaster = Agent(
    model="global.amazon.nova-2-lite-v1:0",
    tools=[mcp_client],   # Strands connects and finds the server's tools by itself
    ...
)

The lambda is a recipe for opening the connection, not the connection itself. Strands uses it to connect when the agent starts and to reconnect if needed.

What we saw

Running it takes two terminals: the server in one, the client in the other. Every roll printed 🎲 DICE ROLL: d6 = … in the server's terminal, which proved the rolls were real. Nova again sometimes rolled fewer than 16 dice and got the drop-lowest maths wrong. That's a weakness of the model, not of MCP: the connection worked every time.

Gotcha

Only one program can use a port at a time. If a server is already running on 8002, starting another fails with "address already in use". Stop the old one with Ctrl+C first, or check what's there with lsof -nP -iTCP:8002 -sTCP:LISTEN.

CH 5A2A: agents working as a team

MCP connects an agent to tools. A2A (Agent-to-Agent) connects an agent to other agents. Each specialist agent runs as its own web server and publishes an agent card at /.well-known/agent-card.json: its name, what it does, and which skills (tools) it has. The Game Master reads these cards to find out who can help, then sends them questions in plain language.

Everyday comparison

The Game Master is a restaurant's head waiter. They don't cook. They take your order, send the rules question to the "rules librarian" and the character sheet to the "records clerk", roll any dice themselves, and bring everything back on one plate (the StoryOutput).

The Rules Agent and its knowledge base

The Rules Agent answers from the official D&D Basic Rules PDF, not from memory. That works through a knowledge base, a pattern often called RAG (retrieval-augmented generation):

  1. create_knowledge_base.py cut the PDF into 979 overlapping passages of about 1,000 characters each.
  2. A small embedding model (all-MiniLM-L6-v2, downloaded once, 80 MB) turned each passage into a list of numbers that captures its meaning. That list is called an embedding.
  3. ChromaDB, a local vector database, stored the passages with their embeddings and page numbers.
  4. When asked a question, the query_rules tool embeds the question the same way and returns the three passages closest in meaning, each with its page number.

This is why the answer about Dexterity checks could cite page 63.

The Character Agent

Three tools: create_character, find_character_by_name and list_all_characters. Characters are saved in characters.json through TinyDB, a tiny database that's simply a JSON file. All storage goes through two functions, save_character and load_characters, so Chapter 8 only has to swap those two to use cloud storage.

Each specialist agent (Rules shown; Character uses port 8001)
def create_agent(context_id: str) -> Agent:
    return Agent(
        model="global.amazon.nova-2-lite-v1:0",
        tools=[query_rules],
        name="Rules Agent",
        description="Rules lookup: fast, page-referenced answers from the Basic Rules knowledge base.",
        system_prompt="...",

a2a_server = A2AServer(agent_factory=create_agent, port=8000)
a2a_server.serve()

agent_factory is a function that builds a fresh agent for each conversation (each A2A context_id). That keeps two players' chats from mixing.

5_a2a_integration/agents/gamemaster_orchestrator/gamemaster_orchestrator.py
mcp_client = MCPClient(lambda: streamablehttp_client("http://localhost:8002/mcp"))
a2a_client = make_a2a_client(allowed_endpoints=["http://localhost:8000", "http://localhost:8001"])

agent = Agent(
    model="global.amazon.nova-2-lite-v1:0",
    tools=[mcp_client, a2a_client],
    structured_output_model=StoryOutput,   # every answer fills these fields
    system_prompt="...",
)

Structured output makes the model's reply fill in a fixed form, the StoryOutput Pydantic model, instead of free text: response (the narration), actions_suggestions (what the player could do next), details (which tools or agents were used) and dice_rolls. A web page can display these fields directly without guessing at the text.

allowed_endpoints is a guest list: the A2A tool refuses to contact any agent not on it.

Remember: MCP vs A2A
  • MCP: "Here's a tool, call it with these inputs." It's a precise function call with a fixed answer.
  • A2A: "Here's a colleague, ask them in words." The other side is an agent that thinks, uses its own tools and replies in language.

CH 6Playing in the web interface

No code in this chapter. A ready-made web page (aws-samples.github.io/sample-once-upon-agentic-ai) talks to your Game Master on your own machine. Enter a character and the server URL http://localhost:8009 (no trailing slash), then play.

Why it said "Load failed"

The web page is served over secure https://, while your Game Master is plain http://localhost. Safari blocks that combination (mixed content) before the request even leaves your Mac, and "Load failed" is how Safari reports it. Chrome and Firefox allow http://localhost. Chrome may ask to "access devices on your local network": click Allow.

CORS was not the problem. The Game Master's CORSMiddleware already allows requests from any website. The server log simply never received a request from the page.

CH 7The harness: a pre-assembled agent

create_harness() from the strands-harness package builds a Strands agent with sensible defaults already switched on. You describe what you want instead of wiring each piece by hand. It still returns a normal Agent, so the rest of the FastAPI app didn't change.

7_strands_harness/gamemaster_harness.py
from strands_harness import create_harness

agent = create_harness(
    model="global.amazon.nova-2-lite-v1:0",              # harness default is Claude Opus 5
    instructions=INSTRUCTIONS,                           # only the game-specific part
    mcp_servers={"dice": {"url": "http://127.0.0.1:8002/mcp"}},
    tools=[a2a_client],
    builtin_tools=[],                                     # turn off shell, file, web tools
    session={"id": "fantasy-campaign"},                # save the conversation to disk
    structured_output_model=StoryOutput,
)

CH 8Production with AgentCore (skipped)

We chose not to run this chapter. For reference, it would take the same four services and deploy them to Amazon Bedrock AgentCore Runtime, so they run in the cloud instead of on your laptop:

  • The dice server, Rules Agent, Character Agent and Game Master become managed cloud services, deployed with the agentcore CLI (which needs Node.js 20+).
  • Calls between them are signed with IAM, AWS's identity system, instead of being open on localhost.
  • Characters and conversations move from characters.json into AgentCore Memory.
  • The rules move from local ChromaDB into a managed knowledge base.

It creates real AWS resources that cost money, and every agent would need the Nova model= change too.

Glossary

Agent
A language model in a loop that can decide to call tools and use their results before answering.
Model
The AI "brain" that reads and writes text, for example Claude Sonnet 4.6 or Amazon Nova 2 Lite.
Amazon Bedrock
AWS's service for using AI models from several companies through one API.
Inference profile
A model ID such as global.amazon.nova-2-lite-v1:0 that lets Bedrock route your request to any region with capacity. us. stays in US regions; global. can go anywhere.
System prompt
Standing instructions that set the agent's role, tone and rules for every message.
Tool
A function the agent may choose to call: roll a die, fetch a URL, query a database.
Vended tool
A ready-made tool that ships with Strands, such as http_request, shell or file_editor.
Tool spec
The name, description and input schema the model sees for a tool. It's built from your function's signature and docstring.
Human-in-the-loop
Pausing before a tool runs so a person can approve or reject it.
MCP
Model Context Protocol: a standard way to serve tools from a separate program that any AI app can connect to.
A2A
Agent-to-Agent protocol: a standard way for agents to discover each other and talk in natural language.
Agent card
A JSON "business card" at /.well-known/agent-card.json listing an agent's name, description and skills.
Orchestrator
An agent whose job is to coordinate other agents and tools. Here, the Game Master.
Structured output
Making the model fill in a fixed form (a Pydantic model) instead of replying in free text.
RAG
Retrieval-augmented generation: look up relevant passages first, then answer from them.
Embedding
A list of numbers that captures what a piece of text means, so similar meanings end up close together.
Vector database
A database that finds the stored items closest in meaning to a query. Here, ChromaDB.
Harness
A pre-assembled agent with defaults (built-in tools, sessions, memory) that you trim to fit.
Session
A saved conversation that can be picked up again after a restart.
Port
A numbered "door" on your computer that a server listens on: 8000, 8001, 8002, 8009 in this workshop.
CORS
Browser rules about which websites may call a server. Our servers allow all of them.
AgentCore
AWS's managed service for running agents in production, with built-in memory and identity.
